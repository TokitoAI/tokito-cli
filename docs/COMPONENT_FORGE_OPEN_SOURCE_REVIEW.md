# Component Forge open-source behavior review

This review selects ideas and observable behavior, not copied source. The shipping CLI remains an original pure-Rust implementation with no KiCad or native CAD runtime dependency.

This is a bounded workflow assessment, not completed reverse engineering of every generator or a complete Rust footprint implementation. The original cuboid WRL is still only a body envelope. The first Rust 0603 footprint slice now serializes a two-pad .kicad_mod candidate with typed geometry and a pinned KiCad 10.0.5 library comparison; see [its evidence and limits](PROJECT_INTAKE_AND_FOOTPRINT.md). Manufacturer land-pattern qualification, other pad/package families, terminals/body surfaces and full library-tool behavior remain open. The twin preparation module operates on existing GLB geometry and does not fill those gaps.

## Decision

For a missing-footprint generator, the primary reference is **KiCad Library Tools/KicadModTree**, not the KiCad CLI. Its documented design separates geometric shape utilities, a footprint node tree, and serialization; Tokito will implement an original equivalent workflow in pure Rust from manufacturer dimensions and pinned source evidence. The KiCad CLI remains a secondary compatibility/reference target for observable `pcb export glb/step/pos/svg` behavior and differential board-export tests. It is not the missing-footprint algorithm and will not be invoked by the shipping Tokito CLI. Do not copy upstream code or claim a complete CLI replica. Use the existing flat-triangle Rust mesh path and deterministic VRML serialization while evidence and the App package boundary are built. Do not adopt Truck, ruststep, EasyEDA services, CadQuery, build123d, or computer-vision systems as production dependencies yet. Dataset component maps and external GLBs are candidate inputs; their identity, geometry, and physical-fit evidence remain separate. For U11, the manufacturer drawing supplies nominal body measurements, but its extracted reflow table is not reliable enough to seed a footprint; U11 is not a missing-footprint case.

KiCad's own documentation describes Library Tools as the generator/test framework for library assets, with KicadModTree used for footprint generation and shape utilities separated from the node serialization layer. Tokito's design adopts those observable boundaries conceptually while keeping its production implementation pure Rust. See the [official KiCad Library Tools documentation](https://gitlab.com/kicad/libraries/kicad-library-tools/-/blob/main/docs/index.rst) and [KiCad CLI manual](https://docs.kicad.org/10.0/en/cli/cli.pdf).

This is an engineering capability assessment, not a complete legal review. The source repositories expose different licenses and asset-level terms; record provenance/attribution for any specific redistributed library file. See [architecture](COMPONENT_FORGE_ARCHITECTURE.md) and [qualification](COMPONENT_FORGE_QUALIFICATION.md).
