# Implementation gates

## Inputs available now

- The CLI carries six pinned real fixtures: SparkFun Basic, community Pico/UNO, NXP MCXA ESC, the official KiCad RoyalBlue54L NFC demo, and the Porcupine routed PCB. These add a real plotted curved outline and a valid board with five physical cutouts plus 607 routed copper arcs. The NFC outline has measured gaps and is expected to fail closed. See [provenance and counts](PCB_FIXTURE_CORPUS.md). The supplied VTOL project remains supplemental, not reference truth. The newer original LumenPnP PCB/stored-Gerber fixture strengthens valid curved and SVG vector-geometry evidence. No certified Tokito target-board package is established.
- The old physical checkout contains an Allegro `.brd` source and supporting NXP files, but it is a separate ignored local dataset with source/licensing/provenance constraints. It is not an accepted KiCad parser fixture.
- `tokito-app-dataset` is the sole target-board corpus. Its routed KiCad candidates, native CAD, Gerbers, BOM/net data, photos and labels have separate provenance/review gates; board-only GLB/STEP assets do not establish a populated assembly or AR registration.

The implemented outline validator is documented in [PCB_TOPOLOGY.md](PCB_TOPOLOGY.md). It is an analytic, bounded topology check for a supported subset, not full CAD/DRC conformance. The canonical import retains a physical stackup and can strictly derive centred outer-copper planes for supported `core`/`prepreg` stacks. The bounded VRML-to-GLB assembly path consumes those planes and requires their separation to match the sourced shell thickness; it still needs independent geometry comparison and actual App consumer validation. Custom-pad rendering and manufacturer validation remain future work.

## Current executable slice

`tokito-cli inspect` reads only KiCad PCB format dates from `20211014` through the reviewed `20260206` and reports the fields it recognizes. It rejects older formats (which can use legacy `module` records) and unreviewed newer versions. `tokito-cli export placements` writes reference, placeholder status, value, library, side, source-frame XY/rotation, UUID, pad/model counts, DNP, and position-exclusion columns. `pcb export pos --format csv` is a separate manufacturing view compared with pinned KiCad 10.0.5 CSVs across Uno, NXP and SparkFun; its absolute-origin side/unit/mirror/SMD/THT/DNP subset is documented in `PCB_POSITION_EXPORT.md`. Repeated graphics placeholders such as `G***` remain UUID-identified inventory rows; duplicate component references and missing or duplicate UUIDs remain errors. The reader consumes no more than 256 MiB from disk and enforces token, node, and nesting limits; parser memory can exceed the source-byte ceiling. Unknown or malformed source constructs can still be outside this prototype's understanding; no faithful-geometry claim is made.

The real fixture tests preserve source identities and inventory counts. Partial SVG imports supported outlines, embedded graphics/text, simple pads/drills, segments/arcs, vias and stored filled polygons, with explicit side/layer selection and omissions. The physical report normalizes supported line/arc/circle boundaries, classifies direct cutouts, refuses invalid topology and retains source locators. Exact-coordinate tests cover saved footprint-relative XY and absolute pad angles, including back-side import without a second reflection. SVG carries source IDs and parent UUID metadata. Fonts, complex/custom pads and unsupported drawing types remain partial.

A v0.1 package writer and native reader preserve/reimport source and validate the fixed manifest, hashes and current-source inspection/placement consistency. The package schema remains unchanged; generated views are exported separately and `mobileImportReady` is false. The public Rust `PhysicalBoardDocument` API provides typed source records, canonical-derived inventory, locator-selected SVG inputs, and GLB exports. The shell export requires valid outline topology and sourced thickness, extrudes curved/cutout outlines, and reports unresolved component identities. `--assemble-wrl` additionally emits the bounded supported local VRML subset as one mesh-bearing `ref:<reference>` renderable node per uniquely identified component, with a pre-retention aggregate triangle budget. Per-model omissions carry status codes. STEP, native desktop schematic adapters, Desktop/MCP wiring and phone import remain unimplemented. See [engine API and limits](CANONICAL_ENGINE.md) and [GLB architecture](GLB_EXPORT_ARCHITECTURE.md).

The current full Windows/Rust verification receipt is the newest `target/delivery/local/*/verification.json`; it records all required local Rust, Clippy, build, CLI, geometry, GLB, model-resolution and v0.1 compatibility gates. The shell GLB journey independently checks its container/accessors, finite f32 positions, board bounds/thickness, triangle winding and paired closed edges, deterministic bytes, default refusal, package input and invalid-outline refusal. The assembly journey checks emitted GLB accessors, one- and two-component exports, mesh-bearing `ref:<refdes>` selector nodes, and a simulated exact-prefix single-component visibility filter. That is a CLI artifact/contract test, not a real App importer or Android renderer test. Placement tests cover the negative-parity frame mapping, signed model scales, front/back placement, and recomputed normals. A separate optional [KiCad 10.0.5 GLB reference capture](KICAD_GLB_REFERENCE.md) exercises an external component node; it is not included in the pure-Rust gate and is not KiCad 10.0.7 parity. Historical inspect/CSV/top/bottom SVG bytes remain exact. These are local Windows results, not Linux/MSRV, full KiCad visual parity or device/AR acceptance. See [local delivery](CI_AND_DELIVERY.md) for the current receipt.

The first Component Forge slice adds a strict nominal body-envelope request and deterministic flat-triangle VRML cuboid. Generic fixture E2E covers the existing model-assignment and selectable partial-GLB path. An optional dataset E2E can be added to the verifier with `-DatasetRepo` and `-DatasetBomReport`; it checks the pinned MCXN236 U11 identity and the correct shell-only refusal. The dataset case does not emit U11 to GLB: the imported board lacks canonical stackup and the combined exporter status is `missing_stackup_or_outline`. No footprint serializer or qualified physical component body exists yet. The optional dataset PR #6 audit checks its pinned GLB provenance, manifest/map coherence, 354 reference selectors and component mesh isolation; it does not establish model-to-PCB UUID crosswalk, physical fit or camera registration. See [Component Forge qualification](COMPONENT_FORGE_QUALIFICATION.md).

## Phased implementation

1. **Format and inspection:** bounded S-expression reader, declared source-version support, board/component inventory, placement export, machine-readable diagnostics.
2. **Tokito package v0.1:** source-and-inventory directory with hashes; current data remains incomplete and is not accepted by the phone runtime.
3. **Canonical board model and 2D views:** Milestones A and B's public source-semantic engine and bounded physical outline topology are locally verified, including historical output compatibility.
4. **Board mesh and component models:** The validated shell path requires explicit partial consent. A first bounded VRML assembly path adds source-derived model placement, SHA-256 provenance and one mesh-bearing `ref:<refdes>` node per component. It refuses incomplete results by default, includes aggregate geometry and diagnostic/report caps, and the CLI E2E exercises two component nodes and the selection filter. Next: independent output/mechanical comparisons, real source/model corpus breadth, and App importer acceptance. Phone import remains separate and must be tested in the app.
5. **Component Forge (ongoing):** A PCB-identity-bound nominal cuboid-envelope command is implemented and tested. Next is an evidence audit, then one package-specific footprint family only after the exact land-pattern table and package identity can be read and independently checked. Do not regenerate U11's existing custom-pad footprint. Its U11 dataset assignment remains withheld from GLB under the combined stackup-or-outline refusal.
6. **STEP:** separate pure-Rust CAD spike; validate units, assembly transforms, topology preservation, and unsupported entity reporting before making it a capability.
7. **Desktop/MCP adapters:** after the engine and package contracts stabilize, add local Desktop and optional local MCP adapters without changing the hosted symbol catalog.
8. **Schematic-to-PCB:** only after Desktop defines physical placement/routing data and stable links from schematic UUID/pin identity to board instances.

## Integration is not yet end to end

The current desktop produces schematics and netlists but not physical board layouts. The current mobile runtime has a digital-twin asset contract but no public package-import API. These are concrete integration gaps. The CLI can establish the shared format and local artifact engine without modifying either repo; adapter and app changes require separate scoped work in those repositories.
