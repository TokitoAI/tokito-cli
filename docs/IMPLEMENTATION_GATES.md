# Implementation gates

## Inputs available now

- The CLI carries six pinned real fixtures: SparkFun Basic, community Pico/UNO, NXP MCXA ESC, the official KiCad RoyalBlue54L NFC demo, and the Porcupine routed PCB. These add a real plotted curved outline and a valid board with five physical cutouts plus 607 routed copper arcs. The NFC outline has measured gaps and is expected to fail closed. See [provenance and counts](PCB_FIXTURE_CORPUS.md). The supplied VTOL project remains supplemental, not reference truth. The newer original LumenPnP PCB/stored-Gerber fixture strengthens valid curved and SVG vector-geometry evidence. No certified Tokito target-board package is established.
- The old physical checkout contains an Allegro `.brd` source and supporting NXP files, but it is a separate ignored local dataset with source/licensing/provenance constraints. It is not an accepted KiCad parser fixture.
- `devboard_ar_dataset` has no actual PCB, photo, or label samples; its GLBs are placeholders.

The implemented outline validator is documented in [PCB_TOPOLOGY.md](PCB_TOPOLOGY.md). It is an analytic, bounded topology check for a supported subset, not full CAD/DRC conformance. Custom-pad rendering, source-derived placement helpers are not a substitute for stackup-derived component placement, GLB scene assembly/selection, and manufacturer validation, which remain future work; the existing partial board-shell triangulation is separately gated.

## Current executable slice

`tokito-cli inspect` reads only KiCad PCB format dates from `20211014` through the reviewed `20260206` and reports the fields it recognizes. It rejects older formats (which can use legacy `module` records) and unreviewed newer versions. `tokito-cli export placements` writes reference, placeholder status, value, library, side, source-frame XY/rotation, UUID, pad/model counts, DNP, and position-exclusion columns. Repeated graphics placeholders such as `G***` remain UUID-identified inventory rows; duplicate component references and missing or duplicate UUIDs remain errors. The reader consumes no more than 256 MiB from disk and enforces token, node, and nesting limits; parser memory can exceed the source-byte ceiling. Unknown or malformed source constructs can still be outside this prototype's understanding; no faithful-geometry claim is made.

The real fixture tests preserve source identities and inventory counts. Partial SVG imports supported outlines, embedded graphics/text, simple pads/drills, segments/arcs, vias and stored filled polygons, with explicit side/layer selection and omissions. The physical report normalizes supported line/arc/circle boundaries, classifies direct cutouts, refuses invalid topology and retains source locators. Exact-coordinate tests cover saved footprint-relative XY and absolute pad angles, including back-side import without a second reflection. SVG carries source IDs and parent UUID metadata. Fonts, complex/custom pads and unsupported drawing types remain partial.

A v0.1 package writer and native reader preserve/reimport source and validate the fixed manifest, hashes and current-source inspection/placement consistency. The package schema remains unchanged; generated views are exported separately and mobileImportReady is false. The public Rust PhysicalBoardDocument API provides typed source records, canonical-derived inventory, locator-selected SVG inputs, and an opt-in partial board-shell GLB. The GLB requires valid outline topology and sourced thickness, extrudes curved/cutout outlines, and reports unresolved component model identities. Pure-Rust point/mesh placement helpers are tested but are not integrated into that GLB scene; it does not emit component models or selectors. STEP, native desktop schematic adapters, Desktop/MCP wiring and phone import remain unimplemented. See [engine API and limits](CANONICAL_ENGINE.md) and [GLB architecture](GLB_EXPORT_ARCHITECTURE.md).

Current full Windows/Rust 1.94.1 verification passed 101 Rust tests (51 library, 9 component-placement, 8 engine API, 1 GLB API, 11 mesh API, 9 resolver API, 12 topology API), formatting, Clippy, release, four-board CLI E2E, topology/reference E2E, GLB E2E, model-resolution E2E and five historical package checks. The GLB journey independently checks its container/accessors, finite f32 positions, board bounds/thickness, triangle winding and paired closed edges, deterministic bytes, default refusal, package input and invalid-outline refusal. The placement tests cover the negative-parity frame mapping, signed model scales, front/back placement, and recomputed normals. The pinned NFC reference comparison matched all 22 plotted Edge.Cuts entities with endpoint tolerance 1e-6 mm and arc-center/radius tolerance 5e-6 mm. Historical inspect/CSV/top/bottom SVG bytes remain exact. These are local Windows results, not Linux/MSRV, full KiCad visual parity or device/AR acceptance. See [local delivery](CI_AND_DELIVERY.md) for the current receipt.

## Phased implementation

1. **Format and inspection:** bounded S-expression reader, declared source-version support, board/component inventory, placement export, machine-readable diagnostics.
2. **Tokito package v0.1:** source-and-inventory directory with hashes; current data remains incomplete and is not accepted by the phone runtime.
3. **Canonical board model and 2D views:** Milestones A and B's public source-semantic engine and bounded physical outline topology are locally verified, including historical output compatibility.
4. **Board mesh and component models:** The first local GLB slice triangulates/extrudes a validated shell with cutouts and sourced thickness and requires explicit partial consent. The remaining selectable-model work must add proven model parsing, per-component transforms/provenance, UUID selectors and model-complete coverage. Phone import is separate and must be tested in the app.
5. **STEP:** separate pure-Rust CAD spike; validate units, assembly transforms, topology preservation, and unsupported entity reporting before making it a capability.
6. **Desktop/MCP adapters:** after the engine and package contracts stabilize, add local Desktop and optional local MCP adapters without changing the hosted symbol catalog.
7. **Schematic-to-PCB:** only after Desktop defines physical placement/routing data and stable links from schematic UUID/pin identity to board instances.

## Integration is not yet end to end

The current desktop produces schematics and netlists but not physical board layouts. The current mobile runtime has a digital-twin asset contract but no public package-import API. These are concrete integration gaps. The CLI can establish the shared format and local artifact engine without modifying either repo; adapter and app changes require separate scoped work in those repositories.
